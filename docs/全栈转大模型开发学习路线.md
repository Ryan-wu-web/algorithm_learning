## 1. 路线定位

这份路线不再以“逐行手写所有代码”为学习目标，而采用下面的协作方式：

```text
Claude 编写样板代码和初版实现
→ 学习者阅读关键调用路径
→ 画出数据流或状态流
→ 修改关键变量做对照实验
→ 主动制造或分析失败
→ 用运行证据完成复盘
```

本月集中学习两条主线：

### 主线 A：大模型训练流程

```text
数据
→ Tokenization
→ Batch / DataLoader
→ Forward
→ Loss
→ Backward
→ Optimizer Step
→ Validation
→ Checkpoint
→ Transformer
→ 最小预训练
→ SFT
→ LoRA / QLoRA
→ 偏好对齐
→ 统一评测
```

### 主线 B：可控 Agent 搭建流程

```text
用户目标
→ 模型决策
→ Tool Call
→ 参数校验
→ 工具执行
→ Tool Result
→ 状态更新
→ Workflow / Agent Loop
→ 预算与终止
→ 记忆
→ 安全与人工确认
→ Trace
→ 回归评测
```

月底目标是：

- 能独立讲清两条流程；
- 能读懂并修改关键实现；
- 能通过实验判断参数影响；
- 能从日志、Loss 或 Trace 定位失败阶段；
- 完成小而完整的训练实验和受控 Agent 实验。

月底**不要求**：

- 从零训练出可用的大语言模型；
- 独立手写所有样板代码；
- 构建生产级 Agent 平台；
- 完成企业级 RAG、Web 平台或部署系统。

## 4. 本机训练环境

已检测到：

```text
GPU：NVIDIA GeForce RTX 4060 Laptop GPU
显存：约 8 GB
驱动报告 CUDA 支持：12.7
CUDA Toolkit / nvcc：13.2
```

这台机器适合：

- PyTorch Tensor、Autograd 和小网络训练；
- tiny Transformer；
- 小规模预训练和 SFT；
- 小参数模型的 LoRA；
- 在兼容条件下尝试极小 QLoRA。

不适合：

- 从零训练真实规模的大语言模型；
- 大参数模型全量微调；
- 多卡或分布式训练；
- 为追求“跑通”而加载超过显存能力的模型。

注意：驱动支持版本、CUDA Toolkit 版本和 PyTorch 自带 CUDA Runtime 不是同一个概念。安装 PyTorch、bitsandbytes 等依赖时，必须根据当时的官方兼容矩阵选择版本，不能仅依据 `nvcc --version` 猜测。

QLoRA 采用双路径：

```text
本地兼容 → 在 8 GB GPU 上运行极小模型实验
本地不兼容 → 完成配置阅读、显存估算和故障分析，必要时再单独决定是否使用云 GPU
```

